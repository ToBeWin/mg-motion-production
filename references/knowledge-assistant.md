# 知识助手：让依据进入答案，并能回到原文

适合知识库、研究助手、企业问答和带来源的 AI 功能发布。先选一个观众能判断的能力：资料被怎样使用、某个回答由什么支持、如何核对出处。TRACE 是其中“答案与引用连续”的原创概念案例；不代表真实模型运行，也不套用到没有来源能力的产品。

## 可复用的设计方法

**先把答案做出来。** 准备问题、资料 ID、具体段落、答案里的主张、引用编号与来源定位；保持一一对应。引用可能只支持一句话，不能让一个编号替整段未经支持的推断背书。真实产品要使用其实际输出；本例用明确标注的自编资料与原文引用。

**分开信息层与运动层。** `data/corpus.json` 是内容源，`data/prepare.py` 生成片中数据与可阅读的答案 HTML/JSON。文档、摘录和答案同时读取同一文本，不在多个 JSX 里分别抄写。`validate.py` 检查来源内容、引用、锚点、相对媒体路径和声音标记。静态链接检查不等同于浏览器交互验收。

**让携带的信息保持身份。** TRACE 中两段摘录各是一层持续存在的预合成：原文位置 → 答案列 → 缩小后的答案 → 品牌收尾。引用编号随摘录一起移动。回看时同一原文图层从画外返回，连线指向实际高亮段落；没有另造一张“看起来差不多”的来源卡。

**空间有分工。** 原生三维文档平面在选择资料时形成轻微深度，阅读时回到正面并停稳；摘录与答案保持屏幕平面坐标，确保文字宽度和引用可读。高分辨率预合成的显示缩放、三维 Z 缩放、相机投影须分别处理。连线端点要用当前父级缩放和位置计算，而非凭画面估计。

**背景服务信息。** 本例从暖白过渡到浅蓝白，用钴蓝区分引用和当前选中来源，浅阴影形成纸面距离。背景不承担额外的粒子叙事。科技感也可以来自准确的字排、对象状态与空间秩序，是否适用取决于产品。

## 本轮返修得出的细节

- 原文变为摘录时，文字可在同坐标直接接替，单独淡入底色和引用芯片。若把整个摘录从透明淡入、同时删除原文字，会出现短暂缺字。
- 先安排移动摘录的通道，再让答案标题和标签出现。中心点没有相撞不代表字框、高亮背景和标题不会覆盖。
- 检查开场与收尾的中间帧。开场口号未离场时不要叠入问题框；答案面板让出标题区域后，再揭示收尾文字。稳定关键画面看不出这些短暂交叉。
- 停留段除了检查关键帧坐标，还要读回中间时刻；自动空间曲线可能让位置在阅读时缓慢漂移。当前辅助函数明确关闭自动空间曲线并处理空间切线。
- 两倍内部尺寸的预合成在主合成默认显示为 50%。动画缩放须带上这个比例；源平面三维 Z 缩放保持 100，避免零缩放影响三维行为。

## 声音与节奏

`production-plan.json` 统一控制资料进入、摘录出现、答案落位、引用点击和回到原文的声音 cue。此例用 100 BPM 的原创音符、合成纸声和轻点击声；长阅读段降低音乐层级，结尾留完整和弦与收音。时长由动作和阅读共同决定，不要求每个词都卡鼓点。

已附 `music.wav`、`foley.wav`、`master.wav`，无需重新安装音乐工具即可重建。改变关键动作时点后重生成音轨；构建器会检查 cue 一致性。最终 AAC 的响度、真峰值、解码结果与主观听审分开记录。

## 运行案例

```bash
python3 assets/knowledge-assistant/rebuild.py --out /absolute/new-project/source --render
```

得到 32 秒 1080p30 成片、`TRACE.ecproj`、原创声音及 `result/答案与出处.html`。默认用已附音轨；加 `--regenerate-audio` 才需要 macOS Swift、系统音色库、NumPy 和 ffmpeg。工程的音轨使用相对路径，复制时保留完整 source 目录。

本片固定为两段短摘录、三个文档与 32 秒横屏布局；长答案、更多来源、不同画幅要重新编排。沿用方法而非只替换标题。`effectcraft/inspect.jsx` 可通过 MCP 读回原生对象身份、停留段、引用坐标与片尾透明度。

实际导出检查、抽帧与新目录重建记录随案例的 `qa/` 提供。用户评价和主观听审仍独立记录，见 [能力证据](capability-evidence.md)。多模态输入、真正的检索/推理和生产部署需要另行制作与验证。
