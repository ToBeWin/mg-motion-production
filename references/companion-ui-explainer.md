# 角色导览 · Companion UI Explainer



## 设计理念：把理解过程变成可见动作

一个常驻向导建立情绪与注意力的连续性；真实或可信的产品空间建立位置；对象状态、指针动作和可见结果建立因果。先回答观众此刻的问题，再给一项动作，最后让结果停稳。这种关系构成风格，角色外形与品牌配色可重新设计。

参考片按“为什么有用 → 它怎样工作 → 具体操作 → 两种方式怎么选 → 做出什么结果 → 复盘与团队”推进。它不是每隔几秒换一张漂亮画面。保持观众的理解负担可控，是图形、相机和声音的共同目标。

### 四个注意力通道

1. **指向**：角色先看向目标、移到目标旁，或指针先定位，再发生变化。避免语音说左边而视线、强调在右边。
2. **尺度**：界面全貌用于定位，特写用于操作，结果正视用于阅读；镜头移动有明确的问题需要解释。
3. **层级**：不相关界面退成低对比背景，当前对象保持清晰。原空间保留，减少认知上的重新定位。
4. **状态**：选择、授权、执行、成功、修改前后可区分。彩光只作强调，不能代替真实状态。

## 场景与变体

| 传播任务 | 应保留的关系 | 设计调整 |
|---|---|---|
| AI / 消费应用介绍 | 向导接住需求 → 调用能力 → 结果 | 有亲和力的动作，减少设置细节 |
| 功能上新 / SaaS 教学 | 完整 UI → 关键操作 → 状态变化 | 更克制的角色、更准确的控件与文本 |
| 新手入门 / 工具接入 | 用户做什么、系统做什么、如何确认成功 | 解释责任边界；必要时保留真实权限步骤 |
| 开发者工具 | 指令 → 执行证据 → 可打开产物 | 终端与文件可读；装饰不遮代码和错误提示 |
| 方案比较 | 固定左右身份 → 同维度比较 → 选择依据 | 颜色辅助语义，不用大小暗示无依据优劣 |
| 团队 / 多 Agent | 角色身份 → 分工 → 交接 → 共同结果 | 不用头像集合冒充实际协作 |
| 生活服务 / 路线规划 | 意图 → 地点/日程关系 → 可调整计划 | 地图可为标明的原创示意；真实路线需核实 |
| 企业培训 / 复杂流程 | 主流程定位 → 局部步骤 → 返回整体 | 降低角色表演密度，增加操作阅读时间 |

短发布片选一个完整因果链；长教程保留分支、条件与复盘。不能把四分钟教程机械压成四十秒，也不能把短 Demo 的留白比例直接放大到长教程。

角色可采用原创几何向导、品牌吉祥物、指针伙伴或克制的符号化主持者。完全去掉持续引导者后，更接近 `luminous-workspace` 或 `precise-ui`；按目标选择，不强塞角色。小型图标和设备优先在设计工具中完成精细造型；真正需要连续体积/遮挡/材质变化时才增加三维。

## 制作流程

### 1. 建立“理解脚本”

每一段记录：观众的问题、关键对象、讲解语句、可见动作、验证结果、下一段继承什么。先从产品中找到具体结果，原片提到的产品能力不自动属于本次产品。

输出一张注意力表：`time / spoken phrase / attention target / state before / action / state after / next anchor`。它同时驱动分镜和声音剪辑。用户只需记住一个选择时，画面不要同时强推三个提示。

### 2. 制作组件和状态资产

按组件手册选择需要的对象，不默认塞满全部组件。设计至少包含普通态、当前态、反馈态，以及最大放大时的版本。角色身体、视线、眼睛、手势和地影独立；设备外壳与屏幕内容独立；真实 UI、鼠标、点击环和状态图层独立。


### 3. 先预演最难的连续关系

优先测试：角色从遮挡后出现；视线先于目标变化；选中组件展开成结果；真实点击改变字段；结果收回而界面仍可定位。一个前景对象可带动转场，但不需要每次用扩圆或闪白。

不要只验起始与结束帧。检查最拥挤的中间帧、文字相撞、虚化遮掉语义、缩放改变圆角和线宽，以及旁白已进入下一句而画面尚未交接。

### 4. 按语义设计节奏

参考的节奏组织是“预告/定位 → 动作 → 反馈 → 阅读”。重要名词先建立，再发生连接。快动作后回到稳定；眼睛与小手不能持续重复抢走阅读注意力。组件入场可从 0.3–0.6 秒、收束 0.15–0.25 秒开始试，但须按距离、尺寸、旁白重新调，不写成原片精准参数。

相机改变尺度时，让旁白内容在到达后或到达附近开始；点击之后再说成功状态。比较段保持双方身份与同维度信息，给选择理由足够时间。

### 5. 声音与字幕




字幕可使用透明背景或与场景匹配的底板。保留可读、跟随讲解、关键词有层级的目的，底板按当前需求决定。与背景共同选色，检查底部字幕和片内控件不相撞。波形、ASR、完整听审和用户评价分别记录。

### 6. 交付与迁移

交付成片、无烧录字幕版、SRT、音乐版、原始音乐与必要分轨、设计/动画/声音工程。重开复制后的项目检查媒体，不只检查原路径。默认在新目录改造案例。

## 没有卡通角色时：持续指针导览

1. **给指针明确角色。** 它是片子的讲解向导，负责定位、停顿、带向结果和复盘。进入阅读区后停稳，避免绕圈或不停点按。普通强调与真实点击要可区分；只有实际可执行控件才配点击环和点击声。
2. **保持真实空间。** 低对比的工作台可以作为背景定位，但进入策划、技能等新任务时必须同步换背景。低透明度的旧界面仍能传递错误上下文，不能因为它很淡就忽略。
3. **让每段回答一个问题。** 目标从哪里开始 → 如何看懂信息 → 如何组织行动 → 成果在哪里 → 团队如何继续。步骤复盘保留已完成项，而非每镜清空重来。叙事步骤标识属于影片，不代表后端实时进度。
4. **指针与控件共享坐标。** 窗口缩放、最大高度限制或裁切改变后，重新计算真实按钮中心和指针尖端位置。验证接近、按下、结果开始出现三种状态，不能只看光圈落点。 持续指针可放进带透明边距的小尺寸原生预合成，保留路径、描边和阴影的可编辑性，再以尖端作为主合成锚点；这样能避免每帧对整画幅重复处理一个小图形的阴影。
5. **声音成熟、轻巧。** 可用留白充足的拨弦键音、柔和木质打击或轻量电子律动；避免把导览做成卡通/游戏音色。短提示声绑定可见变化，旁白时音乐避让。提示词不等于实际听感验证。


## 原生交互与 MG 引导补强（2026-10-31）

按 [跨风格原生交互方法](native-interaction-fidelity.md) 制作真实热点、指针按压、状态响应、遮罩展开、内部滚动、同源局部放大与阅读引导。各路线的字排、空间与节奏分别设计。


## 完整片经验同步：输入、引导与更多 MG（3.30.0）

- **输入框与交接：** 聚焦 → 原文字形输入 → 可提交态 → 按压/释放 → 真实后态；步骤条解释过程，不能伪装成后端运行日志。
- **鼠标与引导：** 区分定位、强调和真实点击；尖端命中热点，按压后再出现响应；讲解目标稳定后才亮出阅读框或路径。
- **MG 组织：** 问题字排 → 向导定位 → 输入与提交 → 真实响应 → 证据展开 → 步骤复盘 → 成果序列 → 品牌收束。
- **节奏与空间：** 指针停稳让观众读，步骤错峰；纯 MG 段交给字排、页面与路径，不让鼠标承担整片表演。
- **声音配合：** 旁白先说明目标或跟随已出现结果；提示声仅对应可见变化，避免游戏化连击声。

共同检查：输入完成态可读、文字等比、光标无重影、工作台不穿透前景文字、热点随窗口变换、反馈不早于点击、同源成果可追溯。不要把全部效果同时堆到一镜。
