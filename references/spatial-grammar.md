# 空间与运动语法

先决定空间表达的关系，再选择技术。深度不是给所有卡片加倾斜；它可以表达从属、距离、聚合、层级、进入内容或回到全局。

| 空间 / 动作 | 叙事用途 | 典型场景 | 容易失败的地方 |
|---|---|---|---|
| 平面编辑式排版 | 强调词义、信息层级与节奏 | 品牌、宣言、数据 | 所有字都同样弹出，观众不知道重点 |
| 2.5D 层级与视差 | 显示界面前后关系、焦点与从属 | UI、工作流、知识结构 | 阴影、遮挡、缩放互相矛盾 |
| 同一画布内相机行进 | 把多个能力/内容组织成一个世界 | 平台发布、多模态、团队协作 | 相机漫游没有揭示信息；文字始终无法读 |
| 材质特写 → 功能全景 | 先让观众感知品质，再理解用途 | 设计系统、控件、实体产品 | 永远停在抽象玻璃，没有回到产品 |
| 焦点 / 路径接力 | 表达因果、数据来源、任务交接 | Agent、检索、工具调用 | 连接线无端点含义，光点跑过即消失 |
| 拆解 → 组装 | 显示模块组成与组合价值 | API、系统、硬件 | 拆出的部件没有真实关联或空间归宿 |
| 有语义的形态变换 | 把前一状态转成后一状态 | 品牌、新能力概念 | 任意物体互变，漂亮但无法理解 |
| 向纵深进入内容 | 从概览进入细节或内容世界 | 创作工具、多模态、搜索 | 长时间穿梭只剩速度，主体丢失 |

## 给每个镜头一份空间约定

记录世界坐标对象、屏幕固定信息、相机方向/焦距/目标、前中后景、深度范围、遮挡顺序、阴影方向和最终阅读构图。UI 中的文字可以保持清晰的正视面，边缘、厚度、环境反射另行处理，不必把整张 UI 变成会反光的金属板。

相机的每次推进、侧移、旋转至少完成一种任务：揭示关系、改变关注对象、从细节回到全局或连接下一动作。阅读时允许停住；持续漂浮会把产品展示变成屏保。

## 转场检查

1. **身份**：前一镜的哪个对象进入下一镜？颜色/编号/形状足够让观众识别吗？
2. **运动关系**：运动是否连续，出发/落点有原因吗？转场速度与主体质量、镜头距离匹配吗？
3. **深度线索**：遮挡、透视、视差、阴影是否指向同一个空间？
4. **阅读归宿**：动作完成后，信息是否落在稳定且足够大的可读位置？

没有必要每次做长转场。动作匹配切、构图匹配切、遮罩接力、同对象变形、相机接镜和直接切各有用途。先建立几种相互一致的转场，再做变化。

## 实际制作中的可复用修正

- Blender 界面面片若采用世界 Y 向上，默认 look-at 的 up 约定可能让相机翻滚。明确计算 right/up/back 基底，先检查文字水平与相机坐标。
- 纯白界面被高光冲白时，先检查色彩管理、光照和材质。必要时用保持颜色准确的正面 UI 材质，另用真正受光的边、厚度与底板表达质感。
- 玻璃依赖厚度、折射、粗糙度、背景对比和光源形状；透明度滑条加模糊不足以复现光学材料。
- UI 叠层跟随 3D 对象时，由每帧投影得到屏幕端点。不要手写一条近似路径，导致镜头动时标注滑开。
- 标记强调线应避开字形。落版前确认离场元素真正离开画幅，不残留半张卡片。

这些是问题出现时的检查项，不要求所有二维项目都建立三维场景。
