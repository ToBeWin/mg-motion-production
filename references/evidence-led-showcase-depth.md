# 实证式产品发布：组件与迁移

从单项任务到成果集合，保持对象身份、坐标与内容连续；具体数量、时间和布局应由项目内容决定。

## 组件需要共享数据与状态

首轮列出的 12 类组件是蓝图。下面补足它们应如何相互连接；原生实现现已落地其中九类组件，三类仍仅为蓝图，逐项状态见结构化研究文件。

### 任务对象

每个任务至少有：`case_id / role / problem / request / skill_labels / capture / result_ids / proof_points / runtime_evidence`。

- 大问题与顶部小问题读取同一字段，不能分别手填后出现不一致。
- 输入框与真实工作台的请求身份对应；若画面使用缩写提示词，应标记为编辑呈现，完整输入仍保留在证据记录中。
- 侧栏结论关联 `result_id` 和页码/区域；只有对应结果出现后，才进入可见状态。
- 用时牌可选。没有运行证据时省略，不能从参考片继承数字。

### 成果对象

每个成果至少有：`result_id / case_id / filename / type / page_or_tab / source / crop / scope_note / thumbnail`。

- 同一结果在工作台预览、局部放大、能力巡览和矩阵中共用身份。
- 截图可变换整体尺度与裁切，但不得单独拉伸图表、移动数值或改比例。
- 将最后成果从巡览视窗移动到矩阵时，用同一内容预合成实例；位置和尺度变化期间继承裁切，进入小格后才做必要的视窗重排。
- 矩阵缩略图主要证明结果种类，不要求读清正文。需要阅读的关键结论应在此前单结果阶段完成。

### 能力导航与集合

每项能力记录：`capability_id / label / result_id / title / emphasis / hold_duration`。

导航激活、标题与结果由同一个索引驱动；不要给三者维护互相独立的硬编码时间。集合布局由成果列表生成，固定画面边距和间距，根据数量计算行列；不强制所有片子使用十项或 2×5。

状态图：`inactive → active → completed_in_film → collection`。其中 completed 仅指影片已展示，不能冒充后台任务完成。

## 迁移与检查矩阵

| 条件 | 需要验证的结果 |
|---|---|
| 问题由一行变两行 | 顶部停靠后仍可读，不挤压窗口和字幕 |
| 报告由横向变纵向 | 保留页面比例；用局部阅读而不是拉伸填满 |
| 成果数由 10 改为 6 或 8 | 自动重排仍有稳定网格，最后成果落入指定格 |
| 从深色变明亮背景 | 文字、强调色、边缘、阴影与字幕整体重配；保留相同的叙事层级 |
| 旁白增加或删除 | 重新分配阅读时长，不能仅整体加速/减速 |
| 同一软件改为其他业务 | 替换真实请求、结果和证据；不能只换片名 |

这些是验证条件，不能整体写成已经通过。这些是适配检查，不自动证明新项目已通过。
