# 高能混合媒介产品发布

风格 ID：`kinetic-product-pop`。用大字排、独立设计的组件、按需选用的立体道具、手绘线条、被放大的操作控件和真实内容成果组成一支产品发布片。字排建立主次节拍，组件设计建立辨识度，空间服务层级，界面动作负责说明，成果负责证明。它不以长时间停在完整工作台为主，也不以全片热烈品牌口号代替产品内容。



## 适用场景与边界

| 场景 | 可迁移的方法 | 必须重新设计的部分 |
|---|---|---|
| 软件 / AI 新产品发布 | 字排揭示能力，控件从抽象符号进入可读操作，输出展开为成果舞台 | 本次产品身份、功能事实、输入与结果、交互前后状态 |
| Agent / 办公与协作平台 | 来源选择 → 任务 → 可复核结果 → 流程复用，使用短促字排分章 | 数据口径、授权语义、来源与责任；概念演示不能充当真实执行 |
| 创意与内容工具 | 立体工具符号连接画布、作品变体和交付 | 作品本身的设计与编辑状态，不用无意义缩略图占位 |
| 开发者工具 / 新功能广告 | 巨幅关键词、代码或参数特写、运行结果及分享动作 | 真实输入、执行反馈、可读字号；装饰组件不能捏造性能 |
| 以软件为主体的品牌广告 / 社媒短片 | 保留品牌道具与核心操作，以快慢变化压缩信息 | 时长、画幅、安全区、无声理解与品牌入口 |

大段文字教程、严肃复杂规则或安静的精密材质摄影通常需要其他主路线。本风格可只作为其中一个章节，不强行添加角色或高饱和色场。迁移方向不是已经完成的多行业、多画幅交付。

3. **组件有状态。** 为开关、来源、输入、提交、处理中、完成、保存设计前后状态。将一套来源名称、颜色和数据贯穿输入与结果。独立保存结果页面和组件源，再送去动画。
4. **按最大镜头尺度设计。** 高倍率文字保留原生或足够分辨率；细小来源在特写时能读清。图形、标题、背景、阴影和字幕同步配色，明亮背景不等于全部铺白或灰渐变。

本机可用 FigCraft 进行关键画面、组件与版式设计，VectorCraft 处理路径/字形/图标，PhotoCraft 处理位图与纹理。Figma、Pen.dev 按项目需要使用；账号或每月天数不足时不应阻塞本地设计链。不要为了工具清单把不需要的应用加入生产流程。

## 运动与空间语法

- **分配不同物性。** 字排可以快速入场并停稳；手绘线条按方向描出；控件有准确点击和响应；硬质键帽保持形状；角色动作需要预备与反应。不同对象不套同一条弹性曲线。
- **改变距离与密度。** 大字 → 组件展开或必要的立体特写 → 关键词 → 控件 → 输入特写 → 成果展开 → 品牌，按本次故事重组。快段需要可辨识落点，结果需要阅读停顿；不是每个镜头都缩放一张卡片。
- **转场携带身份。** 一个标点可以成为操作种子，来源颜色进入输入 chips，任务中的数值进入报告，成果收拢成为复用流程。选择少量真正有意义的连续对象，不强迫所有镜头形变。
- **浅空间解释层级。** 原生 3D 平面与相机用于控件离开平面、多个结果页展开；阅读时保持稳定正面或合理倾角。三维道具用真实连续镜头，不能拿一张渲染图冒充三维动画。
- **按中段检查交接。** 查看按下、转场最满、对象接替、最大透视和结束状态。圆形扩张过早遮满会留下无意义空拍；字体与背板不同步会露底；主体出源画幅后无法在合成中补回来。

## 工具实现与可重建工程


EffectCraft 中使用原生文本、形状、路径修剪、父级、关键帧、三维平面、相机、阴影和字幕。复杂对象/材质在 Blender 中制作；不要求所有任务都使用角色、3D、粒子或仿真。按能力实际验证选择引擎，不从参考外观反推原作者一定使用 AE。

本例实测的交接问题：

- QTRLE MOV 在本轮导入中被报告为 `unknown` 并未正常显示；改用 ProRes 4444 后渲染可见且 alpha 正确。容器有 MOV 后缀不代表编码和透明解释都支持。
- 修改素材 `startTime` 会移动原有入出点。先设开始时间，再显式设置 `inPoint/outPoint`，在出现的头、中、尾实际渲染。
- Blender 本例脚本会跳过已存在帧。更改模型、灯光、相机或材质后必须使旧缓存失效，不用旧帧证明新版本成功。
- SoundCraft 导入轨道不代表选中了轨道，使用导入返回的 ID 设置音量；本机 `automation.set_point` 的 volume 值使用 dB，已与输出 PCM 比较确认。
- 字幕色场分段使用互不重叠的整帧区间。原生透明图层与最终烧录时点来自同一清单，避免颜色切换时两行字幕重叠一帧。

这些是对应版本的实测结果，不是所有版本/编码器的永久限制。通用细节见 [设计工具链](design-toolchain.md)。

## 配音、音乐与字幕

按本次用户选择配音与音乐。此方向适合明快、精确、有停顿的音乐，但具体可选电子、放克或其他音色；根据品牌与实际生成结果选择，提示词和 BPM 不是听审结论。

先让主动作与乐句、重音互相适配，再为重要点击、触碰和转场添加少量声音。不要把每个元素入场都配一个 whoosh，也不要用临时合成旋律替代指定配乐。短生成结果需要重编或重生成，不能未经设计循环凑时长。



本次完成了本地 ASR、分轨/自动化重开、最终 AAC 测量及视觉抽查。当前环境不能直接主观听取音频，**没有完成全长主观听审**；用户已明确认可 v2 配乐，该反馈单独记录；不要把转写、响度、提示词或其他模型的旧意见当作助手完成了主观听审。需要进一步听审时先使用可用的本地能力；未经用户允许不把本地音频上传外部演示服务。
