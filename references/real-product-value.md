# 公众价值与真实产品画面

适用于已有真实软件、希望面向大会观众或公众介绍价值的 MG 发布片。与 `graphic-product-pop`、`luminous-workspace` 等视觉路线组合使用，不是新的风格编号。

需要同时说明业务深度与场景广度时，可读 [实证式产品发布参考研究](evidence-led-showcase.md)：先完整展示少量任务，再用真实成果进行能力巡览与集合。该研究包含组件、动作和原片观察范围；不要把素材真实性或一次任务的用时扩展成所有场景的性能承诺。

## 先回答观众的问题

把能力翻译成可见的变化：原来难在哪里 → 产品实际做了什么 → 人得到什么、可以接着做什么。选择两到三个有依据的主张，避免把全部菜单和技能变成逐项讲解。垂直行业产品仍须保持真实定位，不能因观众跨行业就擅自宣传为所有行业都已验证。

例如经营软件可围绕“看清变化、形成方案、把成果交给团队”展开。它们是叙事方式，具体能力必须由当次产品证明；不把案例目标当已实现业绩，也不把一次运行耗时宣传成所有任务的固定速度。

## 采集与核对

1. 查看用户提供的权威业务视频，记录问题、操作、输出与时间码。没有听到有效语言时，不把 ASR 的填充音当旁白。参考可以确定重点，真实功能仍结合本机产品核对。
   用户明确原片已认可且业务内容、数据可以沿用时，将它作为本次内容基线；源视频中的真实运行页面可直接用于剪辑和 MG 包装。记录出处与统计口径，不必重新运行每项任务或擅自换成通用演示。详见 [授权参考片的完整业务制作](approved-reference-full-film.md)。
2. 在真实应用中选一至两个干净任务，采集原始请求、可见执行或完成状态、成果链接、打开后的内容。既有已完成任务可用于证明；是否需要重新运行取决于本次要求，不为录制无谓重复收费任务。
3. 原始截图与使用版分开保存。记录裁切坐标、来源文件、采集方式；文件页记录原文件与页码。排除账号区、客户个人明细和不属于产品的桌面元素。不要让重画后的虚拟控件冒充真实软件。
4. 实际成果文件可渲染成高分辨率素材；核对与应用内预览相同，不重新美化数据或替换结论。真实生成的演示方案可以用，但保留其中的假设和目标属性。

## 让实采素材仍然具有 MG 设计

- 完整工作台短暂建立产品身份；随后把同一条请求、关键内容或成果链接放大，减少观众的搜寻成本。
- 截图与其局部共享坐标。局部从原来位置靠近，再接到同名结果；不要每个镜头换一个不相关任务，却暗示是同一条执行链。
- 文件行先出现，再打开真实页面。正视阅读后才分层、扇出或组成页面群；用不同页证明目标、节奏、分工等内容。
- 标题负责表达价值，界面负责证明。主标题在大会大屏上能快速识别；不要求远处观众读完所有表格。
- 真实数据图表保持原数值、比例、口径；可用外部引导线或局部特写强调，不做虚构的增长动画。 裁切或放大时同时保留统计截止日和非完整期提示；例如月中数据不能在脱离口径后被观众当成整月业绩。
- 明亮环境、品牌色、文本和字幕统一设计；页面原有深色块可以保留，片子的整体背景按用户偏好决定。
- 主动作与声音标记一起修订：页面进入、局部靠近、文件打开、成果展开应有恰当停顿；不要把旧点击音留在已经删除的按钮上。

## 声明与验收

分别命名“实采界面剪辑”“已完成任务展示”“连续录屏”“概念演绎”。截图的镜头动画不能称为实时生成，真实应用生成的虚拟案例也不能称为真实商业业绩。

检查真实任务到结果的对应关系、局部放大清晰度、动画中间帧、字幕安全区、音量避让与完整解码。技术通过不等于主观听审或会场验收；旧版获得的评价不自动继承给新版。


## 同产品多风格与原生工程

先建立共享事实清单：产品定位、任务身份、原始输入、成果文件、数据口径、演示假设、官方标识与旁白。各风格再选择独立的窗口关系、注意力引导和转场节奏。复用经过核对的声音应记录声源与剪辑轨哈希；新声音仍需重新核对。旧版内容检查和用户好评不自动代表新版视听验收。

静态柔光、渐变与无时间变化的环境可缓存为图像，减少无意义的逐帧计算；同时保留可编辑原生环境合成和更新缓存的方法。主体 UI、文字、指针、字幕与动作继续原生制作。修改缓存对应的设计后必须重新导出；不要把整条影片的扁平视频缓存称为全元素可编辑工程。

以复制后的交付目录验证相对媒体、原生工程重开和关键帧；把完整画面工程与用于快速字幕合成的缓存工程区分命名。客户实采页面不随通用 Skill 分发，只记录可迁移方法与验收边界。
