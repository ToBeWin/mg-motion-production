# 科技产品作为默认主线

用户在 2026-10-26 明确希望更多聚焦科技。默认优先提高科技产品片的内容、画面与声音完成度；既有非科技配方继续可用，用户指定其他题材时照常执行。不要为了维持场景数量增长而自动扩大生产范围。

## 已有覆盖与仍需补足的深度

目录有 24 类传播场景、16 条视觉路线。当前 24 类场景均有实现证据挂接：此前 11 类成片或相关案例，加上 [新补的 13 条独立样片](coverage-implementations.md)。关联案例与专项样片深度不同，更不代表统一品质验收。例如功能演示可支持软件发布中的一段，但不自动构成完整发布叙事。分类数量不作为品质指标。

下表是科技题材的制作重点，映射到已有传播场景；不是新影片的完成清单。

| 科技题材 | 对应既有场景 | 当前基础 | 后续应做深的内容 |
|---|---|---|---|
| 软件 / AI 新能力发布 | software-launch、feature-demo | 品牌色同步与一念成形等概念案例 | 真实产品资产、完整任务、关键操作与结果对照；每条只证明一个主张 |
| Agent / AI 工作流 | agent-workflow、business-process | 一念协作、具体产物及交接方法 | 任务依赖、工具执行中的可见变化、失败恢复与可用交付物 |
| 知识检索 / 研究助手 | software-launch、feature-demo | TRACE 已有 32 秒来源、答案与引用回看概念片，附同源 HTML/JSON；没有真实检索或模型推理 | 接入实际产品证据、真实来源定位与更复杂答案，保持主张和来源对应 |
| 多模态 AI | software-launch、agent-workflow、mechanism-explainer | 可借用对象持续与产物交接方法，尚无专门的完整多模态片 | 输入图像、语音或其他素材真正参与输出，清楚展示关键变化 |
| API / SDK / 开发者工具 | developer-api、feature-demo | PULSE 字段到任务的概念样片 | 可读且正确的代码、实际接入动作、返回值进入应用；有条件再接真实运行证据 |
| 数据产品 / 科研技术 | data-story、mechanism-explainer | DataTalk 同源数据、SIGNAL 原理示例 | 查询到证据、交互过滤、尺度一致、实验条件与推断边界 |

## 默认制作顺序

先按用户实际产品和素材选择任务。没有具体产品时，优先继续打磨软件/AI、Agent、API、数据四条主线，以完整可编辑样片为单位。科技品牌宣言、发布会开场、网站循环和社媒版本作为这些产品的传播延伸，单独满足对应载体的阅读、收尾和声音要求。

需要扩展新案例时优先考虑：

1. **多模态 AI 工作台。** 一个明确任务、少量输入素材、可见处理和完整产物；图像、语音或文本要实际参与结果，不只是装饰性飞入。
2. **有来源的知识助手。** TRACE 已完成第一条具体概念案例，见 [制作方法](knowledge-assistant.md)。后续针对真实产品接入、不同来源与问答复杂度继续打磨。
3. **云服务请求旅程。** 同一个请求贯穿接收、处理、重试或完成，落到应用结果；技术路径要有语义，不以节点数量营造复杂感。

知识助手已有第一条概念样片；多模态与云服务仍是后续候选，不能视为当前已完成影片。用户只是询问范围或调整方向时，先说明现状与取舍，不自动开始无关的大批视频生产。

## 科技题材的视觉与制作要求

- 延续用户的明亮背景偏好：冷白、暖白、浅品牌色与清晰色场。深色可作文字、结构线和小面积标识，不默认使用黑底。
- 用精确排版、层级、光学材料、界面深度、状态连续和镜头焦点表达技术。为每个运动对象指定具体身份、前后状态和目的地。
- 对真实产品先取得界面与输出资产，再编排动作；概念产品明确标为概念，避免把“像真实 UI”当成实际功能证明。
- 一段抽象技术解释最终回到用户能理解的结果；纯品牌段则以识别、主张和记忆点收束，不强塞功能 UI。
- EffectCraft 承担文字、路径、遮罩、重复器、表达式、相机与合成；有实质材质需要时再用 Blender。是否使用某工具不代替画面质量判断。
- 少量信息交错到位，重要结果留出阅读和音乐空间；审核字段移动中的交叉、视差中的字宽、细线压缩和声音落点。

制作方法继续按 [API、品牌与服务案例](brand-api-service.md)、[任务到结果](task-results.md)、[可见证明](visible-proof.md) 和 [光学材质](optical-materials.md) 选择。实际完成与用户反馈只记入 [能力证据](capability-evidence.md)，不把本优先级表写成验收记录。
