# 柔光工作台与成果叙事

风格 ID：`luminous-workspace`。完整软件工作台建立位置，镜头靠近关键操作，同一个任务连续成为报告、演示、网页或其他可交付成果。明亮环境、持久输入对象与可读结果共同组织影片。



## 适用场景

| 传播任务 | 可见的内容链 | 设计重点 |
|---|---|---|
| AI 办公、Agent 与 SaaS 发布 | 请求 → 来源 → 处理 → 多种成果 → 交付 | 同一任务与资料持续存在，结果有实质内容 |
| 单功能更新、操作引导 | 操作前 → 关键触发 → 变化 → 可使用结果 | 少量精确特写，控件、光标与反馈保持因果 |
| 研究、知识与文档工具 | 资料 → 依据 → 判断 → 文档或演示 | 来源与统计可核对，阅读时停稳，长内容在遮罩内滚动 |
| 开发者与自动化工作流 | 问题 → 代码/调用 → 测试 → 输出或部署 | 使用本次真实代码、响应与状态，不编造成功执行 |
| 业务服务流程与客户案例 | 真实输入 → 处理步骤 → 交付件 → 可核对价值 | 结果资产与案例事实先于包装；示意内容明确标注 |

适合“把能力展示清楚”的产品传播。品牌情绪片、硬件材质片和纯文字宣言可以选其他路线，或在本片中作为短章节使用。本风格与 `editorial-product` 的区别：后者让大字排与持续编辑承担主要节奏，本风格以工作台定位、持久任务对象及多格式成果舞台为中心。不要把两条路线简化为不同背景色。

## 设计原则

- **先设计结果。** 报告有可复核内容、演示有明确主张、网页有完整布局。来源、结果与文件名相互对应，不能用无意义卡片代替功能。
- **空间有锚点。** 开场用完整界面交代位置；特写回答“正在做什么”；结果展示回到可读构图。输入条、任务标题或窗口边界至少有一种能贯穿相关章节，但不要求每条片保留相同控件。
- **浅空间也有层级。** 分清环境、表面、正文、强调、次要信息与字幕。柔光是环境设计，阴影解释前后关系；不要只把所有对象放到同一灰蓝渐变上。
- **内容决定密度。** 主动作区给结果，短章节标题给价值，附属说明退后。为最大放大倍率准备文字与矢量清晰度。缩小界面时优先保证主信息可读，不要求每个工具名都能在手机上辨认。
- **转场交接对象。** 明确保留什么、退出什么、进入什么。细点纹理、模糊、纵向位移或遮罩用于完成交接，不宜全程覆盖。相邻正文不要在高不透明度下长时间重叠。
- **快慢服务理解。** 操作和交接可以快，结果与品牌识别需要停留。重复控件采用一致响应，关键变化建立差异；无意义弹跳、持续漂浮和每步一声 whoosh 会稀释重点。

## 制作流程

### 1. 查看参考并写清观察边界

先用 ffprobe 确认时长、帧率、画幅与音轨，再查看全片和关键动作。记录前后状态、关注点、空间锚点与声音观察范围。稀疏抽帧不能证明精确曲线；没有音轨就不能分析原片配乐。不能由视觉效果断言原作者的软件和插件。


### 2. 定义任务、结果和状态

写一句任务及一套有关联的结果。制作共享内容清单：项目身份、源文件、关键结论、图片、文件名、输出格式、可核对数据。实际产品优先使用真实功能与输出；原创概念明确标注，不把动画按钮或手工制作文件声称为真实 Agent 执行。

为输入、处理中、结果、修改和交付建立命名状态。决定哪些内容需要保持同一身份，哪些变化必须让观众看到。不要沿用历史案例品牌；有缺失事实时缩小表达范围，不虚构性能或客户收益。

### 3. 独立设计资产，再组织运动

需要多人协作与组件布局时用 Figma，路径、图标和矢量版式可用 VectorCraft，分层位图、纹理与影像整理可用 PhotoCraft。工具按资产需要选择，不以用了多少软件衡量完成度。

可使用共享设计数据生成 SVG，并在矢量设计工具和合成工具之间同步文字、形状及内容身份。

素材至少保留必要的文字、形状、路径、颜色角色、尺寸与文件关联。内容图可以是位图；需要放大的界面文字优先保留矢量/原生层。若采用截图，按最大镜头尺度制作，不把低分辨率整屏截图反复拉大。

### 4. 建立连续合成

先预演完整工作台 → 操作特写 → 第一件结果这一最难连接，再扩展成果类型。把背景、成果舞台、持久输入条、内部内容与字幕分开。页面滚动使用明确的窗口裁剪，固定工具栏不跟着正文滚动。

本例在 EffectCraft 0.17.0 中使用原生文本、形状、位置/缩放/透明度关键帧、阴影、Gaussian Blur 和显式遮罩；按实际 API 返回核对效果属性。组件采用两倍内部尺寸，引用缩放相应减半，内部父级统一放大；有遮罩时同步处理坐标与切线，不能只放大容器。

检查转场中段，而非只比较端点。本例第一轮相邻结果短暂交叠成两层正文，后将退出和进入透明度错开，让舞台保留、内容接力；不把具体延迟值写成所有影片的固定规则。UI 内文字保持自身比例，阅读时不随边框非等比拉伸。

### 5. 配音、配乐与同步字幕

配音与配乐优先采用当前用户已配置并授权的工具；其他选择见 [配音与音乐](audio-options.md)。有声与静音用途分别设计，不强制每条官网循环都加旁白。音乐要支持明亮、清楚、专业或本次品牌指定的气质；可以尝试温暖电钢琴、轻电子、圆润低频或稀疏节奏，但提示词不等于实际音色。

先实际听候选，再选择、剪辑和混音。短曲不能未经设计机械循环成整片。音乐生成参数和实际时长按所选工具核对。

剪接与结束要尊重实际乐句。本例最终取连续片段保留生成曲尾，入口和尾部轻渐变，没有循环和变速。若其他项目的片尾不自然，应重选乐句、重编或重生成，不能把渐弱到零等同于音乐已经完成。

配音的停顿与重音服务内容；按实际发声制作字幕，轻声尾部保留，不能只按响度阈值裁掉词尾。有同音品牌时结合发音和画面核对，自动转写成常用同音词不自动证明错读。字幕采用与画面相配的色彩、透明背景及独立安全位置，核对每个镜头的对比与遮挡。

只为重要点击、交接或完成反馈加少量动作声。旁白时音乐避让，旁白结束后保持自然起伏，最后一句及乐曲尾音留出空间。保留旁白、音乐、音效、SRT、ASS 与无字幕版。具体测量和模型辅助审查方法见 [全长声音审查](listening-review.md)；它们不等于人工专业监听。

如果用户认为音乐过大，先调整声部及避让包络，再检查最终混音。把音乐降低后，又将整段强制归一化回原来的综合响度，会部分抵消调整。参数根据实际音轨确定。时长变化后重新选连续乐句、编排主要动作声并重新测量编码后的响度，不能沿用旧听审记录。动作反馈声与背景音乐承担不同作用。

### 6. 以最终文件验证和交付

- 全片解码并核对时长、帧数、音轨和最终编码响度/峰值。
- 看结果阅读帧、最大放大倍率、密集转场、遮罩边缘、字幕与最后一帧。
- 完整检查最终配音和纯音乐版本，核对旁白、音乐性格、剪口及尾部。
- 重新打开对应的结果资产；区分解析检查、实际画面检查和应用内交互检查。
- 复制源目录后用相对资源路径重开工程并重渲染关键帧；写明字体、工具与生成素材依赖。

浏览器或其他工具拒绝某种访问时，记录没有完成的验证，不用换入口绕过政策，也不把文件存在写成浏览器播放成功。

## 新参考深化：从成果展示到可见编辑


**主画面可以由多个窗口共同解释一件事。** 窗口有不同职责：原始资料、提炼结果、操作面板、对照成果。用共享文件名、选中内容或对象迁移说明它们的关系；不是把同样卡片复制两份。主窗口先建立，另一窗口在有内容可展示时出现，原窗口让位。保证标题、焦点、阅读方向与间距可辨。

**编辑前后态要提前设计。** 为同一对象保存“修改前 / 选中 / 指令 / 修改中 / 修改后”状态。请求要具体且可视觉核对，例如突出一项指标并保留来源；操作之后确实改变字号、位置、对齐或布局，原数值、名称与出处继续对应。仅加光标、选框、加载条或完成提示不能证明修改有效。

**镜头接近服务操作，后退服务比较。** 全景用于建立位置，中景读内容，近景看选区与指令；触发动作后让变换和结果有独立时间。不要在一个短段同时高速缩放、滚动、打字与重排。缩放镜头时把光标、选框、工具条、输入框和被编辑内容放在同一坐标空间；保留在主合成的迁移对象必须按投影坐标匹配交接。

**重排改变几何，不拉坏材质。** 圆角面板尽量动画矩形的宽高，避免非等比缩放让圆角和描边变形；文字独立调整统一比例或字号。结果文件、缩略图和动画使用同一内容与版式目标。按改变后的视觉状态重建 PPTX / HTML 等真实产物，避免影片升级而文件仍是旧版。

## 真实产品适配：持久任务与多窗口交接

- **保持任务身份。** 完整界面先建立产品；原始请求从其真实位置放大，再回到同一位置。转到另一项任务时切换任务名与工作台，不把独立的策划案例伪装成同次分析自动产生的下一步。
- **窗口有不同职责。** 原工作台让位，报告进入；同一报告再接到原图表。附件列表的真实预览入口连接同名 PDF，PDF 的摘要页与分工页并置。页面顺序和文件归属必须可以追溯。
- **成果先可读，再展开。** 先给单页正视阅读时间，再形成对照或成果群。不能一出现就缩成远景拼贴，也不靠虚构增长、伪状态或循环光效证明能力。
- **界面尺寸服从层级。** 按真实长宽比约束最大高度，同时给顶部标题、任务标识和透明字幕留空间；全景 UI 可以不可逐字读，近景的请求/结果必须清楚。用实际中间帧检查，不能只验两个端点。
- **声音随交接修订。** 换窗口、放大、打开附件、并置文件分别安排少量落点，配音时间与字幕保持一致；音乐需适合宽松、温暖、明亮的软件空间。具体音色、节拍与避让量按新声源确定，不把案例参数当风格标准。

## 完整片经验同步：输入、引导与更多 MG（3.30.0）

- **输入框与交接：** 输入条是任务锚点；提交后等比收拢到工作台内或停靠一侧，先保持不透明，再与真实后态完成接替。
- **鼠标与引导：** 指针、选区、引导线与控件共享父级和坐标；局部放大使用同一源内容，工具栏不随正文滚动。
- **MG 组织：** 完整工作台 → 输入特写 → 同一任务提交 → 主窗口让位 → 依据与成果并置 → 内部滚动/局部阅读 → 成果归位。
- **节奏与空间：** 动作幅度克制但关系明确，镜头接近时不同时滚动与重排；快交接后保留宽松阅读。
- **声音配合：** 轻触与少量气流提示交接；旁白贴着结果出现，配乐连贯有留白，不给每次窗口移动都加声音。

共同检查：输入完成态可读、文字等比、光标无重影、工作台不穿透前景文字、热点随窗口变换、反馈不早于点击、同源成果可追溯。不要把全部效果同时堆到一镜。
