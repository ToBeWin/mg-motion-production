# 按传播任务选制作配方

先选一个主场景，再选视觉语言、镜头方法和实际工具。24 个配方是可执行的策划入口，当前均有关联实现证据；其中新补的 13 类有独立样片，见 [实现与边界](coverage-implementations.md)。这不意味着已有 24 条通过商业验收的成片。结合多个用途时，以一条主证据链为骨架，其他场景只借用必要段落。

当前默认聚焦科技产品，先读 [科技方向与制作优先级](technology-focus.md)。下列目录继续保留全部用途；不要因为存在某配方就自动扩展到与本次科技任务无关的题材。

## 读取与使用

完整的素材要求、镜头链、连续关系和检查项保存在 `assets/scenario-catalog.json`。按需读取一个配方，不必把整个目录装入上下文：

```bash
python3 scripts/plan_scene.py --list
python3 scripts/plan_scene.py --show developer-api
python3 scripts/plan_scene.py --scenario developer-api --title "本次产品发布" \
  --duration 25 --style technical --aspect 16:9 --out /absolute/new-project/plan
```

生成 `brief.md`、`production-plan.json` 和与命名视觉标记绑定的 `cues.json`。这些是规划文件，继续用本次产品与素材完成关键画面、预演、动画、声音和视频输出，不能把 JSON 当作成片交付。

时长是策划起点，不是平台规定。规划器按整帧分配并提示阅读预算不足；固定时长时优先精简叙事，不把教程或数据阅读强行加速。用户已经授权制作时，生成计划不是另一个审批关卡。

`--aspect` 支持 16:9、9:16、1:1、4:5；`--size 2560x720` 可记录特殊屏幕。换比例须按 [画幅与场景交付](delivery-adaptations.md) 重排，不是只改尺寸或裁切。

## 选择依据

- 软件与 AI 发布仍优先把输入、动作、反馈、可见结果做实；品牌材质段可做引子，但不能替代功能证据。
- 工业、角色、地图、实拍跟踪依赖相应资产或数据。缺资产时先补关键资产或明确示意范围，不靠抽象图元假装完成。
- 交互反馈需要验证目标运行时；MP4 演示不能被称作已交付 Rive / Lottie 或前端组件。
- 已有样片与用户认可按 [能力证据](capability-evidence.md) 逐项记录；新场景继承方法，不继承验收结论。
