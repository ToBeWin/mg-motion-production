# 从三种用途出发：API 发布、品牌宣言、服务广告

对应 `assets/scene-expansion/` 的三个独立原生案例。它们补全既有 24 场景中的三个完整示范，不把“增加三个成片”重复计作新增三个场景配方。

本轮用户明确不喜欢黑色背景。后续制作默认使用明亮中性空间、暖纸色或品牌色场；深色可作文字、线条及小面积标识。历史深色案例留作研究，复用前按当前偏好重新设计。用户之后另有指定时遵循新方向。改变背景时同时重配前景、阴影、边缘与字段色，不能仅做全片反色。

| 用途 | 可见主张 | 连续对象 | 最终画面 | 色彩与声音 |
|---|---|---|---|---|
| PULSE API，24 秒横屏 | 自然语言返回可供应用使用的结构 | due_text / owner / task 三个字段值及 req_024 | 同值落入 task_024，保留调用方式 | 冷白空间、纯白面板、深蓝字、绿蓝赭字段；112 BPM，稀疏脉冲与确认声 |
| SHIFT，18 秒横屏 | 让想法向前一步 | 成对的前倾斜线及向前方向 | 同一母形缩成标识，与品牌字组合 | 奶油白、浅蓝和钴蓝；124 BPM，强弱变化与少数重击 |
| LOOP，26 秒竖屏 | 每份请求在每一步都有回应 | SR-024 申请单与商品照片附件 | 同一申请显示寄出，品牌承诺收尾 | 暖纸色、白单据、森林绿与橙色分支；96 BPM，轻纸声与柔和器乐 |

## API：返回值必须有去处

先设计一个观众能理解的应用结果，再反推所需字段。片例从“周五前，林岚完成首页草稿。”提取三个字符串。三个值各用一个预合成与一个主合成图层，先在句中出现，再进入 schema、可读 JSON 和任务卡。颜色和文字保持身份，键名、括号与面板按阶段变化。代码不是墙纸；请求和响应结构要相容。

转场不要求所有字段同步、同速。此例最初 owner 与 task 同时直线移位，在中间态交叉。修订为 owner 先向左让出通道，task 短暂等待再进入标题位置，截止描述留在右侧。检查路径交叉时同时考虑字宽、字号变化、运动模糊和前一镜尚未消失的标签。

JSON 稳定阅读约 9.3–13.65 秒，结果阅读约 15.3–19.3 秒；音乐在这些窗口下降。字段到位才给确认声。收尾保留结果和 `POST /v1/extract`。此接口及看板为概念示例，没有在线调用或性能宣称；“周五前”保留为截止描述，没有冒充已解析的具体日期。

迁移到模型/SDK 发布时，替换为真实且最小的代码片段、异常边界、返回值和文档入口。更长代码需要新排版与时长，不用缩到不可读来适配旧画面。

## 品牌：从一个母形构成完整视觉系统

先定义比例、方向与含义，再建立变化规则。SHIFT 的两个前倾斜线表达前进：从标识比例放大覆盖画面，回缩为中景主体；同形重复器组成运动纹样，用字形 alpha 遮罩显示在“发生”内部；最后再次覆盖并回到品牌组合。

EffectCraft 中具体使用：三个文字条带遮罩、形状重复器、轨道遮罩、路径、运动模糊与表达式。覆盖转场层只在需要的时段存在，位置/缩放表达式引用母形；不能为了最终转场把母形移到整个时间线最上层，导致前面文字被盖住。斜切路径放大时必须覆盖四角，而不仅是中心宽度。

快动作和完整阅读交替，9.65 秒色场切换与声音重击一致。最后的组合保持到片尾。品牌开场适合继承这种语言，但真正发布会片需要另做屏幕尺寸、观众距离、出场交接和尾音；付费广告还需要真实行动入口与平台安全区，本片不能直接证明这些版本已完成。

## 服务：流程图必须有具体交接物和异常出口

主物件不是四个节点，而是带身份、原因、附件和状态的完整申请单。以纵向角色通道适配竖屏；单据依次与顾客、客服、仓库、通知对齐。缺资料时出现橙色回路，附件补入同一单据，状态变成资料完整后再前进。末尾回到放大的原申请，不凭空换另一份结果。

主标题和当前状态承担主要信息；单据其他细节用于证明连续，不要求观众逐字阅读所有条目。小屏审看时特别检查状态字号和附件是否遮住标题；确需读完详细业务规则时，增加特写或拆成两条。

迁移到售后、预约、审批、物流或 B2B 交付时，先核实角色、交接对象、异常与完成条件。不要把一个案例的“已寄出”套成另一个业务的“已完成”，也不要编造 SLA、支付、审核或真实履约。此例全部为虚构流程，数据文件记录的是固定片例，不是通用工作流程序。

## 明亮背景要与主体一起设计

PULSE 用浅冷色环境与更白的主体区分层次；字段从浅色点缀改为足够深的绿、蓝、赭色，边缘改为浅蓝灰，阴影收薄。SHIFT 用浅长春花蓝替代原深色段，并同步改用深字；钴蓝色场保留浅色字。LOOP 保留暖纸色、柔和接触阴影和折角。不要把三片统一成同一种白色卡片模板。

浅色渐变与颗粒先在 16 bpc 内部合成，再检查实际 8 bit H.264。使用低强度静态颗粒，避免阅读段背景闪动。字形、线条和背景对比以实际导出帧为准。

## 工程与复现中容易忽略的细节

```bash
python3 assets/scene-expansion/rebuild.py --out /absolute/new-project/source --render
python3 assets/scene-expansion/rebuild.py --out /absolute/brand-copy/source --render --only brand
```

重建不依赖工作区其他工程。保留相对音频路径，重建入口拒绝覆盖非空输出目录。`validate_inputs.py` 检查固定片例结构、状态时间和音频 cue 一致性；改变时长/画幅/服务流程需要同时修改 JSX。它不把结构检查写成真实产品运行。

- **2× 预合成。** `U.add` 的初始 50% 只是起点；每个动画缩放关键帧都要乘父子合成的分辨率比例。`X.scale` 已做逻辑换算。只修第一帧会在中段重新放大。
- **原生执行结果。** EffectCraft 0.16.0 的脚本可能以进程成功退出但 JSON `ok:false` 返回错误；构建器必须检查 JSON。导出后再检查文件、解码和实际帧。
- **片尾保持。** 通用标题组件的出场淡出不应自动套到片尾主张。最后一帧与同屏其他对象保持一致，声音单独渐收。
- **声音重建。** 附原创音符和合成动作声，使用主机音色库渲染；音色库和字体不随 Skill 分发。分轨位于归一化前，精确 master 通过两遍归一化脚本重建。最终 AAC 需要再次测量。

实际成片共 2,040 帧完整解码，86 个时间点抽帧审看，三场景原生读回与新目录重建；导出测量与检查摘要见 `assets/scene-expansion/qa/evidence.json`。这些检查支持结构、画面和文件的当前结论；没有完成全片实时播放/主观听审，也没有替用户认定商业品质验收。
