# 产品界面与功能发布

适合 AI/SaaS 新能力、创作工作流和功能说明。主线是“用户想做什么→发生什么操作→系统怎样反馈→得到什么结果”。每个视觉变化应帮助理解这条因果关系。

## 先确定可演示内容

真实产品使用真实截图、可控测试数据或有依据的界面重建。缺少实现依据时使用“概念演示”，不要虚构已经上线的能力。用于讲述过程的 UI 不必在视频里真的可点击，但界面状态和光标行为必须自洽。

将关键状态集中建模，例如输入内容、当前方案、选中色板、生成进度、导出结果。画面、缩略图、全屏预览和片尾都从同一状态取值，别在每镜单独硬编码。

## 相机与阅读

- 一个镜头只要求观众关注一个主要区域。输入完成后给出足够阅读时间，再推动镜头。
- 相机推进到预览区时，围绕实际预览中心计算缩放与位移；边缘 UI 自然离开画面，避免另起一块全屏内容造成跳切。
- 光标沿可理解路径到达真实按钮；按下、反馈、松开顺序一致。点击后不要让光标长期压住刚生成的结果。
- 大标题进入时，旧标题先退出它的占位区。可以同时移动，但要在连续帧中检查文字是否互相穿插、卡片是否遮掉字的关键部分。
- 三个卡片的假透视必须保持边缘与阴影一致。三角形映射的接缝需要检查，别以单帧漂亮代替连续运动检查。

## 转场与状态继承

输入卡片扩张成工作台时，把工作台直接画在卡片的圆角遮罩里。全屏作品退回方案图库时保留同一作品、相位和颜色。选色后让当前作品平滑过渡，导出预览和结束页延续该颜色。

跨镜头用全局时间或连续映射：`sourceTime = a + (globalTime - start) * speed`。不要在相邻镜头随意重置源动画时间。需要冻结时明确冻结的是哪一帧、为何有阅读停顿。

临时替换共享色板后用 `try/finally` 恢复。缩略图缓存键应包含时间和主题/状态；对象作为键时需稳定序列化，不能把所有主题对象都折叠成 `[object Object]`。倒序 seek 与顺序渲染应该一致。

## 节奏与声音

操作前留预期，操作后留反馈，结果页留阅读。输入、点击、选色和完成提示可以发声，滚动和普通控件出现通常不需要逐一发声。产品版配乐的鼓点密度和高频装饰可低于品牌版，关键点击附近适度让出响度。

进度条必须与完成文案同一时间源；完成声跟随状态变为完成的帧，而不是机械地对齐 4 秒小节。转场扫频可稍微预告动作，其峰值更适合跟随速度峰值。最终以播放检查节奏，cue 表是设计依据而非听感证明。
