# 实证式产品发布 · Evidence-led Product Showcase

以真实任务与成果支撑产品传播；品牌身份、具体业务、数据和素材按新项目重新提供。

## 核心理念

**先用少量完整任务证明深度，再用一组可见成果展示广度。** 观众先认可产品解决了一个具体问题，再理解它还能覆盖更多工作。最后用一句品牌主张概括人的收益，而不是继续堆菜单。

基本句式：岗位与问题 → 一次明确输入 → 产品处理证据 → 可打开的成果 → 两三项价值摘要 → 有依据的效率证据。几个案例之后，切换到能力巡览和成果集合。

这是一种真实软件演示与 MG 编辑包装结合的产品发布风格。MG 主要承担标题层级、输入呈现、窗口尺度、信息摘要和章节组织；产品内容承担证明。环境、色彩与明暗根据本次品牌设计。


## 视觉体系与空间

- **固定舞台**：画面背后的光场保持统一，主体换章时不必重新建立环境。可按品牌选择适合的浅色或深色环境。
- **三层阅读**：大标题先说明问题；真实窗口证明发生过什么；旁边短句说明应该记住什么。窗口正文不承担全场观众逐字阅读的职责。
- **稳定版式**：深入案例的成果窗口约占画面宽度的四分之三，右侧为摘要和用时牌。顶部章名稳定；窗口内部滚动，外部解释留在原位。
- **两种标题尺度**：提出问题时字大，产品开始演示时缩小并移到顶部。不是把巨大标题一直压在界面上。
- **白色产品内容与环境分离**：浅色 UI 的窗口边缘、少量阴影/光晕和留白建立层级。圆角和外框只是承托，不能比报告更抢眼。
- **二维为主、轻量景深**：样本可见的关键动作是缩放、位移、透明度、文字显露、画面切换和窗口内容滚动。没有证据把它归为复杂三维材质片，也不能从观感断言使用了 AE。

## 可复用组件

每个组件应有可编辑的名字、内容、状态和入出场方式；真实产品截图不伪装成可逐控件编辑的原生 UI。

| 组件 | 关键状态 | 注意事项 |
|---|---|---|
| 岗位问题组 | 单项入场 → 建立 → 退场 | 问句优先采用目标受众的语言 |
| 章节身份条 | 序号、岗位、任务类型 | 切换业务时必须同步更新 |
| 问题标题 | 大字建立 → 顶部小标题 | 保持同一句、同一任务身份 |
| 输入框与能力标签 | 空白 → 输入中 → 输入完成 → 交接 | 原片有编辑化输入表现；新片需区分设计呈现与真实操作 |
| 产品工作台视窗 | 建立全貌 → 关键回复 → 成果入口 | 让真实内容有可定位的位置 |
| 成果预览视窗 | 看板 / 文档 / 表格 / 演示文稿 | 保留文件或报告身份、页码与必要口径 |
| 价值摘要侧栏 | 一项 → 多项累计 → 留读 | 摘要必须在当前结果中找得到依据 |
| 效率证据牌 | 暂不出现 → 结果后亮出 | 原片标注的用时不是所有任务速度承诺；复用必须另有记录 |
| 扩展桥段 | 少数案例 → 更多场景 | 切换叙事层次，不只是清屏过渡 |
| 能力导航条 | 未激活 → 单项高亮 → 集合态 | 属于影片导航，不冒充软件后台进度 |
| 成果矩阵 | 单窗口 → 多项入格 → 稳定集合 | 使用刚刚展示过的结果，避免突然混入无关截图 |
| 品牌落版 | 价值主张 → 标识 → 简短标语 | 结尾保持，不继续追加细节 |


## 动作与制作

问题递进 → 同一标题停靠 → 输入与提交 → 真实窗口 → 对应成果与摘要 → 新章节 → 能力巡览 → 最后成果连续进入集合 → 品牌落版。可用遮罩、位置、等比缩放、透明度、路径描绘和视窗裁切完成；详细组件契约见 [连续动作与迁移](evidence-led-showcase-depth.md)，可执行组件见 [原生制作](evidence-led-showcase-production.md)。

输入控件、点击热点、响应和真实成果必须对应。区别实录、编辑回放与概念示意；没有可核实的数据或用时不做承诺。根据可读性和旁白重新安排时长；播放结果需要检查源数据、字幕、声音与用户观看条件。
