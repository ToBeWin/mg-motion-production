

## 什么时候选

适合软件、AI 工作空间、知识与内容工具的发布片：用一个具体输入，让观众看见结果怎样出现、怎样修改，以及怎样交给下一位使用者。也可用于研发工具、协作流程和引导片，但要重新设计相应的代码、对象或操作结果。没有可见产品状态变化的纯品牌宣言，优先考虑动态字体等路线。

`software-ui` 更侧重常规界面的可信操作；本路线通过稀疏大字与密集产品内容的交替、明显的镜头尺度变化来组织发布叙事。`fold-design` 重点是视觉作品的主题、尺寸和版式变化；本路线重点是内容经过输入、编辑与交付后，意义和用途如何向前推进。无需把每个产品都改成文档工具。


## 设计与运动语法

| 层次 | 保留的方法 | 在新项目中落实 |
|---|---|---|
| 信息节奏 | 大字表达一个主张，完整界面证明结果，特写解释关键变化 | 按内容安排稀疏与密集段落；不让全片停在同一工作台，也不让口号取代结果 |
| 内容设计 | 结果本身是一件完整设计资产 | 先完成可读的文档、代码、图表或作品；建立字阶、对齐、图例和真实内容，避免空白卡片与伪装饰数据 |
| 视觉系统 | 明亮平面、清楚字排、有限强调色与克制层次 | 定义背景、表面、正文、次级信息、强调和字幕角色；用边界、遮挡和适量阴影区分前后 |
| 对象连续 | 同一内容贯穿输入、生成、改写与交付 | 为关键对象保留名称和前后状态；来源可缩成标签，结果可以被选中和修改，不无理由切成另一份成图 |
| 镜头尺度 | 完整界面建立位置，推进到关键文本或操作，再返回结果 | 改变距离要揭示信息；计划最大放大倍率、裁切范围和阅读停顿，不把所有元素一起缓慢漂移 |
| 操作反馈 | 选择、输入、执行和反馈各自可见 | 指针和按钮有实际目标；让改写发生在选区内，分享有明确权限、动作与确认状态 |
| 转场 | 文字、线、边界或同一结果承担接替 | 可以采用局部滚动替换、轮廓生长、内容缩入缩略图；检查中间帧和意外空白，不默认整屏淡入淡出 |

根据内容和品牌分别设计底色、文字、选区及强调色；不要只换背景色就称为新设计。

## 制作流程

1. **定义一个具体的前后变化。** 写清输入内容、触发动作、可见结果、一次有意义的修改和交付方式。不是每条片都必须出现这五步；按实际产品能力删减或改写。概念演示与真实软件运行分开记录。
2. **先设计结果与状态资产。** 完成一件足以单独展示的结果，再补输入框、来源、选区、修改面板和交付状态。文字、图形和控件保持可编辑。需要设计系统时使用 Figma，需要精确路径时使用 VectorCraft；位图、材质或摄影成立时再使用 PhotoCraft / Blender，不为工具数量添加环节。
3. **做镜头尺度和连接的预演。** 先试完整结果→操作特写→变化→返回结果。确认文字放大后仍清晰，选区与指针同属正确坐标空间，再安排片头与品牌收尾。
4. **用原生层建立时间轴。** EffectCraft 保留文本、路径、描边生长、组件预合成、选择状态和关键帧。可用同一设计数据生成 SVG 与原生图层，避免两套版面逐渐不一致。样片不是录制实际软件，应按概念说明。
5. **把实际声音排入动作。** 按本次用户选择配音与音乐。逐句生成后依据实际发声放置字幕；主操作才给明确音效，音乐给旁白让位。按听到的音乐选择与剪辑，提示词不证明生成结果的曲风。保留原始音乐、语音和独立分轨。
6. **检查最终编码文件与可移交源。** 查看放大镜头、转场中段、修改后的结果和片尾；对照实际发声检查字幕。完整声音模型审查、文件检查与用户认可分别记录。复制到新目录后重开或重建原生项目，验证媒体路径和关键画面。

## 工具实施与检查

放大预合成时检查文本清晰度；必要时增加内部尺寸并同步补偿缩放，遮罩与内部坐标也要一起调整。滚动文本使用显式遮罩并检查中间帧。交接时检查意外空拍，保留有意的留白。

