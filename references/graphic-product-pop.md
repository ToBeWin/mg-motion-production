# 图形组件产品发布 · Graphic Product Pop

风格 ID：`graphic-product-pop`。把品牌图形、文件、票签、任务、报告等独立设计成有辨识度的对象，以动态字排、分层开合、轻透视和带有对象连续性的转场，连接产品操作与可读成果。画面明亮、有节奏；组件的形状和内容先成立，再用动效放大它的特点。


这条路线由 `kinetic-product-pop` 的混合媒介研究发展而来，选用设计组件作为主资产，不要求三维道具。与一般 `precise-ui` 的区别在于组件本身有广告级图形设计和品牌性格；与 `bold-brand-pop` 的区别在于产品操作、同一内容和成果承担主要叙事。两者可按项目组合，但保持统一的美术系统。


## 适用场景

| 场景 | 设计重心 | 结果应当是什么 |
|---|---|---|
| 软件 / AI 发布 | 核心组件、品牌字形、放大的操作与状态变化 | 真实功能输出或明确标注的概念成果 |
| Agent / 办公 / 协作 | 来源 → 任务 → 成果 → 复用，同一名称和数值贯穿 | 报告、计划、可分享文件或后续行动 |
| 创意工具与功能更新 | 有设计感的画布工具、选区、变体与输出 | 完整作品及其可见修改，避免空白卡片 |
| 开发者产品 | 请求、工具、响应做成可阅读的图形组件 | 有依据的代码、响应或部署状态 |
| 业务流程 / 服务说明 | 资料包、工单、凭证和流程节点 | 一件事如何被完成，谁接着使用 |
| 产品型社媒广告 | 保留一条短操作链，强化尺度和节奏 | 一眼可懂的收益与明确入口 |


## 设计理念与素材方法

**先选信息对象，再决定外形。** 资料、任务、结果各有自己的轮廓；文件夹、带切口的票签、折角报告比三张相同圆角卡片更容易区分。新产品要重新选择有语义的对象，不能把案例文件夹贴到任何行业。


**小组件优先用设计软件。** FigCraft / Figma 做版式、文字和组件状态；VectorCraft 做轮廓、标志与路径；需要位图纹理时使用 PhotoCraft。文件的折角、细描边、轻渐变、虚线和层间关系可由二维设计完成。只有镜头实际需要体积、环绕视角、折射或真实照明时，才加入 Blender。用金属材质和更高采样修补不合适的资产路线，往往不能改善设计。

**按动作拆层，并保留坐标关系。** 文件夹分底层／纸张／封面，纸张在封面后滑动；报告和状态章独立；连接线使用可描出的原生路径。相关部分使用共同画布、明确锚点和命名，文字跟随其载体，不在运动中单独漂移。票签切口、纸张折角和层叠边缘构成识别点，细节数量按最大镜头尺寸决定。

**保留设计源与真实交接结果。** 案例保留 `.figcraft`、`.vectorcraft`、SVG 和透明 PNG；组件以不同素材层进入 EffectCraft，控件和字排另用原生形状／文本。设计源内的可编辑文字，不等于 PNG 进入合成后仍是文本。导出倍率按镜头最大放大计算；2 倍只是本例选择。核对透明边缘、字体、渐变与阴影，阴影在合成中控制更方便。

## 镜头与运动

可重组的叙事链：品牌起点 → 组件展开 → 关键操作 → 可读结果 → 复用或下一步 → 品牌结束。每段回答一个问题，避免所有镜头都是漂浮面板。

| 动作 | 用途 | 制作关注点 |
|---|---|---|
| 短句错峰出现并停稳 | 引入、章节和口号 | 读完再切，不给每个字相同的大幅回弹 |
| 纸张开合、票签进入、状态章出现 | 建立组件性格 | 各自改变位置／角度／比例，硬纸保持形状 |
| 连线描出、对象交接 | 说明信息怎样流动 | 线头落在相关对象；遮挡关系能解释来源与去向 |
| 局部靠近与回到操作 | 让提示词、按钮和状态看清 | 放大后文字仍清晰，提交动作有命中与响应 |
| 报告正视后分层展开 | 展示成果及其结构 | 先阅读，再倾斜；不能让前景盖住关键数字 |
| 同色／同形接替 | 连接章节和品牌 | 先核对转场最满和对象交接时刻，控制无内容停顿 |



## 制作流程

真实软件的商业宣传先读 [公众价值与真实产品画面](real-product-value.md)。图形组件用于组织和强调信息；关键输入、任务状态与成果须尽可能来自真实产品。大会片可以宏观叙事，但不能用全部虚拟卡片替代真实性，也不能把实采截图的镜头动画称为实时操作。

2. **做关键画面与组件。** 至少覆盖展开态、操作态、成果态，统一轮廓、字排、色彩和字幕角色；准备前后状态与分层资产。先看设计是否吸引人，再增加动画复杂度。
3. **预演最难的连接。** 把组件进入、阅读、离开与相邻镜头一起输出短片；先暴露遮挡、比例、空间和节奏问题。局部修订时沿用用户已认可的其他部分。
4. **完成原生动画。** EffectCraft 负责文本、形状、父级、路径修剪、遮罩、状态响应、轻透视和字幕。保存独立组件与主时间轴，关键动作由同一套命名时间标记约束。
5. **编排声音。** 使用用户指定或适用的本地、程序化或在线声音工具；SoundCraft 保存配音／音乐／音效分轨与音量自动化。先对齐乐句和主动作，再点缀少量点击、接触和过渡声。
6. **导出与复查。** 检查关键状态、转场中段、字幕、声音起止和完整媒体解码；保存三种有声版本、无损声音、工程及可重建来源。源目录复制后核对关键画面和媒体链接。

## 配乐搭配

根据品牌选择器乐、节拍与音色，给旁白和阅读留出空间。点击、展开、转场与音乐乐句协调；先检查实际音乐再剪辑，不以提示词或预设节拍代替听审。用户可使用已有声源、本地生成、程序化音乐或授权在线服务，参见 [配音与音乐选项](audio-options.md)。

## 字幕与容易出问题的地方

- 字幕按真实发声安排，透明背景，颜色随场景明暗调整；浅底深蓝、蓝底白字是本例配色。不要固定黑字或统一底板；检查它与主体、脚注是否相撞。
- 纸张和文字分别运动可能露底或穿过封面；组件拆层时保持共同画布、锚点和遮罩关系。
- 报告扇出和票签重叠可能遮掉指标。至少让核心结论与必要口径在稳定阅读段完整可见；不能只核对起始帧和结束帧。
- 图形扩张遮满过早会产生多余空拍。检查铺满到下一元素出现的间隔，也检查音乐在此处是否有对应停顿。
- 修改素材 `startTime` 后重新设置 `inPoint/outPoint`，并实际渲染进入、停留、退出。文件存在不代表正确时间能看见。
- 在放大后的成片帧检查细字、描边、渐变、透明边缘和阴影；不要用设计画布缩略图代替这一检查。
- 纯静帧、成功导出、测量通过和用户评价是不同证据。此例已有用户画面与音乐认可；迁移到新品牌、新比例、新行业仍按新结果判断。



- 已迁移：短句字排、标点到对象的接续、放大的权限/输入操作、资料到结果、成果页面展开、方法沉淀与团队复用、明亮色场和信息密度切换。

继续深化时，先增加有设计意图的对象关系和动作句式，再按确有空间需求加入三维。可根据品牌设计浅底、品牌色场和信息密度反差；造型与材质应服务内容。像素级复刻程度、模型数量和工具数量都不等于商业表现。

## 完整片经验同步：输入、引导与更多 MG（3.30.0）

- **输入框与交接：** 真实输入保持正视与等比，提交后由输入承托/文件轮廓接到实际窗口；前景输入不与后景正文同时半透明重叠。
- **鼠标与引导：** 短距离到位、停顿、按压、反馈；阅读时指针退出重点区域。描线落在文件或控件上，强调完成后交给成果。
- **MG 组织：** 价值字排 → 真实输入 → 提交 → 文件到页面遮罩 → 正视成果 → 分层扇出/回正集合 → 品牌接力。
- **节奏与空间：** 组件动作紧凑，允许较大的尺度反差；正文与数字先正视停稳，再进入轻透视。
- **声音配合：** 键入轻而稀疏，按压绑定可见动作；展开与收束匹配乐句，文字较长时让音乐降低密度。

共同检查：输入完成态可读、文字等比、光标无重影、工作台不穿透前景文字、热点随窗口变换、反馈不早于点击、同源成果可追溯。不要把全部效果同时堆到一镜。
