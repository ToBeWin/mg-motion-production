# 功能发布片：资产、操作与结果的连续制作

适用于软件功能发布、设计系统、内容批量编辑、跨端同步和有可见输入/输出的 AI 产品。完整范例在 `assets/feature-release/`；品牌是“一念 STUDIO”，演示内容是虚构设计品牌 CLUE。不要把它说成实际产品录屏或已经上线的功能。

## 把结果做成值得观察的作品

v2 用三张相似的圆环图案证明改色。v3 换成建筑刊物的网站、海报、移动端：照片属于同一编辑主题，但图片裁切、标题、导航、按钮、信息密度分别设计。共享品牌，不等于复制同一版面。

先检查观众最终拿到的东西。软件片要有可信的内容和状态；数据片要有可追溯数据；硬件片要有可信材料与结构；角色片要有可表演的姿态和绑定。缺的资产先补齐，不用空卡片和抽象粒子代替结果。

范例的建筑影像由内置 image_gen 生成，来源与最终提示词保存在 `assets/provenance.md`。照片是虚构场所的视觉素材。UI、字号、字色、按钮、形状、控制面板均为 EffectCraft 原生图层；不把整个界面烘焙为不可编辑的 AI 图片。系统字体不随包分发，换机须复查字形与换行。

## 以一个动作组织全片

范例的证据链：旧品牌色作品 → 三种触点 → 放大主色面板 → 点击新色 → 手机先给出可见反馈 → 回到同三份作品的全景 → 逐项观察结果 → 收束价值。

`Brand controls / Accent` 是唯一颜色源，网站按钮、海报字标、手机按钮与控制面板通过表达式读取同一属性。动作在 6.6 秒（30 fps 的第 198 帧）发生，7.04 秒完成过渡。不要为每个触点分别手写近似的颜色与时间；那容易留下不同步的状态。

这类方法可以转用于品牌字体、语言、图片资源、价格标签、主题配置与表格驱动图表。每项仍需自己的数据和界面，不把颜色控制脚本当作这些功能已经实现的证明。

## 运动决定看哪里

操作段先靠近颜色面板，让光标与选中色可读；结果段退回全景，再给网站、海报、手机各一个观察距离。对象从相邻画面的位置进入和离开，保留身份。缩放和位移要揭示新信息。

横屏样例的长距离位移使用不同的入/出缓动影响（76 / 32），海报和手机相对主物件延后约 55 / 110 ms；轻微漂移、点击压缩、状态过渡和标题揭示另行安排。这些值只适合此例。不要把所有对象、所有动作套同一零速曲线，也不要机械地给所有 UI 加回弹。

文字的揭示用与文本尺寸相符的预合成。全画布线性擦除可能从离文字很远的位置开始，造成无效等待。长移动前退出旧标题，主体接近稳定位置后进入新标题，密集检查两者交叠区。

竖屏的图片上移曾穿过固定标题与品牌栏；最终用独立的标题区遮挡层界定运动舞台，稳定画面保持完整，进入/退出阶段在标题下方被遮住。横屏则让开场标题在卡片开始进入前退出。检查转场中间状态，不能只看两端都正确。

## 特写的清晰度和坐标

本例的设计资产按 2 倍内部尺寸创建，再在主合成中以相应比例显示。更高的输出分辨率不能修复低分辨率的中间预合成。

EffectCraft 0.16.0 本轮遇到的实际问题：直接给脚本对象的 `comp.width/height` 赋值没有得到预期的工程尺寸变化，图层却已放大，预演出现裁切。可靠实现是在 `addComp` 时传入正确尺寸，再按坐标体系构造内容。不要把未报错等同于引擎状态已变更。

本例中图形/文字的坐标与比例翻倍；已按高密度创建的子合成只改变在父合成里的位置，保留其正确锚点和比例。否则容易二次放大、偏移或裁切。对真实导出检查近景、嵌套图片和手机圆角边界。

## 横竖屏与声音分别编排

横屏 24 秒，竖屏 18 秒；竖屏重新布局三种触点，把操作面板与手机排为两列，减少结果巡览，保留点击和全景证明。它不是横屏居中裁切。不能保证任意文案或资产比例直接替换后仍成立。

配乐是原创 100 BPM 音符编排，电钢琴、马林巴、低音由本机 macOS AVAudioUnitSampler 离线渲染；点击、柔和气流与确认音由确定性 DSP 生成。系统 DLS 音源留在宿主机，不随包分发。竖屏拥有独立收尾，不直接截断横屏乐曲。

`notes.json` 记录音符，`cues.json` 记录声音时点。点击前降低音乐密度/电平，6.6 秒放点击声，随后安排轻的状态确认音。不要为了所有物件都有声音而堆满音效。分轨为 `music.wav` 和 `foley.wav`，母带另经 loudnorm；分轨相加还原预母带，不承诺直接相加得到处理后的母带。`compose.py` 保存实际处理链。

## 重建与检查

```bash
python3 assets/feature-release/rebuild.py --out /absolute/new-project/source --render
# 若需要重新演奏原创乐曲，而非使用已经包含的分轨：
python3 assets/feature-release/rebuild.py --out /absolute/another-project/source --regenerate-audio --render
```

渲染需要已安装 EffectCraft CLI，允许 `--cli /verified/path`；音频重建另需要 macOS、Swift、NumPy、FFmpeg。已有分轨可直接用于其他机器的工程，字体仍需复查。脚本向新目录复制；直接运行 `build.py` 遇到已有工程会拒绝覆盖，确认要重建该副本时才用 `--replace-project`。

检查真实导出的 MP4：完整解码、时长与帧数、音轨响度和峰值、动作前后密集帧、最长位移的中间状态、标题阅读、片尾停留。重开相对路径工程并渲染至少一帧，验证可移交性。静帧、结构检查和信号测量均不能替代全片实时播放和听审。实际本轮检查范围在附带的 QA 记录中；用户是否认可另行记录。
