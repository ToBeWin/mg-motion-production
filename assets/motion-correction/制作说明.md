# TRACE v10 · 从问题到依据

16 秒、1920×1080、30 fps 的软件 MG 方向验证片。针对上一轮“画面更整洁，但很多片子没有达到目标 MG 效果”的反馈，重点重做连续对象、信息转场与动作层次。它不是九条样片全部重做，也不是已经获得用户认可的旗舰基准。

## 制作逻辑

| 时间 | 动作与信息 |
|---|---|
| 0–1.6 秒 | 输入问题，提交按钮收缩、回弹，焦点括号建立视觉身份 |
| 1.6–3.0 秒 | 同一输入条收至顶部，三份资料错开展开 |
| 3.0–4.8 秒 | 两段相关原文高亮并出现引用编号，第三份资料不被选入 |
| 4.8–6.3 秒 | 两段摘录沿上下分离路径进入答案；第一张资料底板扩成工作区 |
| 6.3–9.1 秒 | 答案、来源、编号停稳，保留阅读时间 |
| 9.1–10.3 秒 | 点击引用 2，原文进入展开的来源详情；答案侧稍后保留副本，避开重叠 |
| 10.3–12.3 秒 | 答案与原文并置，观众确认对应关系 |
| 12.3–16 秒 | 原来的括号与引用点收成品牌标记，字标错开落位，结束句停稳 |

图形、文字、预合成、形状尺寸、路径、遮罩、关键帧和图层顺序均由 EffectCraft 原生项目实现。工程是 16-bit；H.264 交付为 8-bit Rec.709。没有把整张软件截图的缩放当作全部动画。

TRACE 是概念产品，画面数据来自同一份 `data/validated.json`。实际没有连接在线检索、模型推理或真实软件后端。

## 文件与重建

- `TRACE-MOTION.ecproj`：可编辑工程，所有音频引用为相对路径。
- `effectcraft/trace-motion.jsx`：本段的动作与布局。
- `audio/edit-plan.json`：已选音频来源、剪辑点与事件声。
- `audio/timeline.json`、`captions.srt`：句级字幕与配音时段。
- `audio/master.wav` 及三条分轨：新剪辑后的配音、音乐、动作声。
- `caption-themes.json`：本片使用 TRACE 蓝紫字幕，无底板、无描边。

依赖：EffectCraft CLI（本次 0.16.0）、Python 3、FFmpeg；重新混音需要 NumPy，检查拼图需要 Pillow。字体使用 macOS 的 Hiragino Sans GB、Helvetica Neue、Menlo。CLI 默认位于 `~/Library/Application Support/EffectCraft/bin/effectcraft-cli`，可通过 `EFFECTCRAFT_CLI` 环境变量指定。

从此目录执行，复制到新的工作目录：

```bash
python3 rebuild.py --out /absolute/new-project/source --render
```

需要从随包原始选段重新混音时增加 `--remix`。默认复用已经审听过的 `audio/master.wav`。脚本拒绝写入已存在的目录；在新的副本里修改后，使用 `python3 build.py --replace-project --render` 更新该副本。

成片输出到 `source` 的上一级，包含中文字幕与不烧录字幕两个版本。字幕是旁白字幕，界面文字两版均保留。

## 声音与检查范围

复用先前选中的 IndexTTS2 五句语音和 MiniMax Music 素材，按 16 秒新时间线重新剪辑、交叉淡化、压低旁白下的音乐并混合事件声。没有重新调用 TTS 或音乐生成，也没有用程序合成旋律替代 MiniMax。

检查记录包括实际 MP4 完整解码与 AAC 测量、原生对象与指定碰撞区间、字幕文本及整帧时段、关键转场密集抽帧、全长模型辅助声画审查。模型审查不能代替人工监听或客户审美接受；模型对动作和结尾的描述需要与实际帧交叉核对。具体文件与审查版本见随包 `qa` 与总交付记录。

`audit_native.py` 只检查两组指定摘录对象的可见边界，不是全场景碰撞检测器，也不给动效质量评分。连续叙事成立仍须以正常速度的影片和用户反馈判断。
